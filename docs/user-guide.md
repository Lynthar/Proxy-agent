## 开始之前

### 您需要准备什么

| 准备项目 | 说明 |
|---------|------|
| **一台 VPS 服务器** | 需要有 root 权限（管理员权限） |
| **SSH 连接工具** | Windows 推荐Xshell或PuTTY；Mac/Linux 使用自带终端或termius |
| **域名**（可选） | 如果需要使用 TLS 加密协议，需要一个指向您 VPS IP 的域名 |

### 支持的系统

硬性要求是 **bash ≥ 4.3**（低于它脚本直接拒绝运行），服务由 systemd 或 OpenRC 管理。在此之上，脚本按发行版家族识别：

- Debian / Ubuntu 及其衍生版（Ubuntu 16.x 会被拒绝）
- CentOS / RHEL 系，含 Rocky、Alma、Fedora（CentOS 7 的 bash 是 4.2，会被拒绝；SELinux 处于 enforcing 时脚本会退出，见 [SELinux 说明](selinux.md)）
- Alpine（请先执行 `apk add bash wget`，脚本依赖 bash）

不在这几个家族里的发行版会被拒绝。能通过检查不等于推荐使用：已过官方支持期的系统版本拿不到安全更新，软件源与内核也可能过旧，请尽量选用仍在支持期内的版本。

### 系统架构

- amd64 / x86_64
- arm64 / aarch64

### 重要提示

- 本脚本需要以 **root 用户** 运行
- 首次安装前，建议使用一台 **干净的 VPS**（未安装过其他代理软件）
- 如果之前安装过其他代理脚本，建议先卸载或重装系统

## 安装脚本

### 第一步：连接到您的服务器

使用 SSH 工具连接到您的 VPS，确保您是以 root 用户登录。

如果您使用普通用户登录，可以执行以下命令切换到 root：
```bash
sudo -i
```

### 第二步：下载并运行安装脚本

复制以下命令，粘贴到终端中并回车执行：

```bash
wget -P /root -N https://github.com/Lynthar/Proxy-agent/releases/latest/download/install.sh && chmod 700 /root/install.sh && /root/install.sh
```

> **网络问题？** 如果下载失败，可能是您的服务器无法访问 GitHub。可以尝试使用加速镜像或手动上传脚本文件。

### 第三步：以后如何打开脚本

安装完成后，任何时候只需输入以下命令即可打开脚本菜单：

```bash
pasly
```

## 首次安装代理服务

运行 `pasly` 后，您会看到主菜单。选择 **选项 1（安装）** 开始安装。

### 安装流程概述

```
┌─────────────────────────────────────────────────────────┐
│  选择内核 → 输入域名 → 申请证书 → 配置协议 → 生成账号  │
└─────────────────────────────────────────────────────────┘
```

### 详细步骤

#### 步骤 1：选择内核

```
请选择核心安装
1. Xray-core
2. sing-box
```

**如何选择？**
- **Xray-core**：主要支持vless系列协议
- **sing-box**：支持更多种类协议

#### 步骤 2：输入域名

```
请输入域名
例如：www.example.com
```

**注意事项：**
- 域名必须已经解析到您的 VPS IP 地址
- 解析生效可能需要几分钟到几小时不等
- 如果没有域名，部分协议（如 REALITY）不需要域名也可使用

**如何检查域名是否生效？**

脚本会自动检测，如果看到类似提示：
```
当前 VPS IP：1.2.3.4
域名解析 IP：1.2.3.4
```
两个 IP 一致即可继续。

#### 步骤 3：申请 TLS 证书

脚本会自动使用 Let's Encrypt 申请免费证书。

> 脚本每天检查证书，到期前 15 天内自动续期（失败次日重试），无需手动操作。

#### 步骤 4：等待安装完成

安装过程会逐步显示进度，例如：
```
进度 1/N：安装工具
进度 2/N：申请 TLS 证书
...
进度 N/N：生成账号
```

> 总步数 N 由本次选择的内核与协议组合决定，常见为 5–12 步。

#### 步骤 5：记录账号信息

安装完成后，脚本会显示您的账号信息，包括：
- 连接地址和端口
- 各协议的配置参数
- 订阅链接
- 二维码（可用能调用摄像头的客户端扫描）

## 拼车管理

几个人合用一台 VPS 时，拼车功能按人统计流量：每人可以有月配额、到期日和可用协议，超额或到期自动停用，下个周期自动恢复；整机流量按服务商的计费口径另记一份，快用完套餐时提醒车主。车主维护一个 JSON 配置文件，脚本负责把它落到 Xray 的配置里。

只支持 Xray 内核，默认关闭。没开过拼车的机器，配置和行为与以前完全一样。

下面用一个例子贯穿全节：机器上装了 VLESS+TCP+TLS_Vision（协议 0）、VLESS+WS+TLS（协议 1）和 VLESS+Reality+Vision（协议 7），已有三个账号 `owner`、`alice`、`bob`。

### 开启拼车

选择 **7. 用户管理** → **6. 拼车管理** → **4. 开启拼车**。开启前脚本逐条检查，有一条不满足就说明原因并拒绝：

- 内核是 Xray-core，版本不低于 1.8.12；
- 没有安装 Hysteria2 或 TUIC——它们在 Xray 内核下跑在 sing-box 里，流量计不到，成员换个协议就能绕过配额；
- 系统里有 `flock` 命令；
- cron 守护进程在运行。

开启时脚本会：

1. 如果 `/etc/Proxy-agent/carpool/members.json` 还不存在，按现有账号生成一份，例子里的三个人都是不限额、不限期、可用全部协议；
2. 打开 Xray 的按用户流量统计，统计接口只监听 `127.0.0.1`；同时让 Xray 不走 splice 转发（服务环境里设 `XRAY_BUF_SPLICE=disable`）——走 splice 时，Vision 协议（0 和 7）的下行要到连接断开才计进统计，内核重载时还在传的那部分整段丢失；
3. 在 crontab 里加一条每 5 分钟运行一次的统计任务（`install.sh CarpoolTick`）。

成员名取自现有账号名（去掉协议后缀）。改名等于给这个人换订阅链接，所以生成的文件沿用原名。

### 配置文件 members.json

把例子改成：alice 每月 100 GiB、年底到期；bob 不限流量，但只能用 TCP 和 Reality 两个协议；owner 不动。这台机器的套餐是每月 1 TB，服务商进出双向都计。

```json
{
  "resetDay": 1,
  "notify": { "label": "拼车", "warnPercent": 80, "digestHour": 8, "expireNoticeDays": 3 },
  "billing": "both",
  "plan": { "sizeGB": 1000, "warnPercent": 85 },
  "members": {
    "owner": { "quotaGiB": 0,   "expire": "",           "protocols": "all" },
    "alice": { "quotaGiB": 100, "expire": "2026-12-31", "protocols": "all" },
    "bob":   { "quotaGiB": 0,   "expire": "",           "protocols": [0, 7] }
  }
}
```

| 字段 | 取值 | 说明 |
|------|------|------|
| `resetDay` | 1–28，默认 1 | 每月几号清零，按服务器的本地日期。最好和服务商的计费周期对上：按开通日重置的，看客户区里的下次续费日。那一天是 29–31 号时填 1，拼车比服务商晚一两天清零；别填 28，那样拼车先清零，成员的新额度会用在服务商的旧周期里 |
| `notify.label` | 1–32 个字符，默认 `拼车` | 页面标题和通知里显示的名字。脚本不会自动填主机名或 IP |
| `notify.warnPercent` | 0–100，默认 80 | 成员用量到配额的这个百分比时发预警，0 关闭 |
| `notify.digestHour` | 0–23 或 `null`，默认 8 | 每天几点之后发每日摘要，`null` 关闭 |
| `notify.expireNoticeDays` | 0–365，默认 3 | 到期前几天提醒，0 关闭 |
| `billing` | `"out"`、`"both"` 或 `"max"`，默认 `"both"` | 服务商的计费口径：只计出站、进 + 出、进出取大。见下面「计费口径与整机流量」 |
| `plan.sizeGB` | 非负整数，默认 0 | 套餐每月多少 GB，照抄服务商的数字：1 TB 填 1000（按十进制，1 GB = 10⁹ 字节）。0 表示不设套餐，只记整机用量、不提醒 |
| `plan.warnPercent` | 0–100，默认 85 | 整机用量到套餐的这个百分比时提醒车主，0 关闭。和 `notify.warnPercent` 互不相干 |
| `plan.interface` | 可选，网卡名：字母或数字开头，可含 `. _ -`，最长 15 个字符 | 整机按哪块网卡计。不写就自动找主路由表里默认路由所在的网卡；出站走策略路由（比如 WireGuard 按 fwmark 分表）的机器认不出来，要在这里写明 |
| 成员名 | 字母或数字开头，可含 `. _ @ + -`，最长 64 个字符 | 两个名字只差大小写、或 `-` 之前的第一段相同，会被拒绝——后一种两人会共用一份订阅文件 |
| `quotaGiB` | 非负整数，0 表示不限 | 按计费口径算的用量上限，1 GiB = 2³⁰ 字节。`billing` 是 `both` 时，上下行合计每用 1 GiB 算 2 GiB |
| `expire` | 空，或 `YYYY-MM-DD` | 到期日当天仍可用，次日停用 |
| `protocols` | `"all"`，或协议编号数组 | 只能写已安装、由 Xray 承载的协议：0、1、3、4、7、12；0 和 7 只要装了就必须包含 |
| `uuid` | 可选 | 写了就用这个 UUID；不写则沿用账号现有的，新成员自动生成 |

协议编号：0 = VLESS+TCP+TLS_Vision，1 = VLESS+WS+TLS，3 = VMess+WS+TLS，4 = Trojan+TCP+TLS，7 = VLESS+Reality+Vision，12 = VLESS+Reality+XHTTP。

文件里出现不认识的字段会被拒绝，拼错的字段名不会被悄悄忽略。只有一种错误查不出来：`members` 里同一个名字写了两次，读文件时只保留后一个，前一个静默丢失。

### 改完怎么生效

| 改了什么 | 何时生效 |
|----------|----------|
| `quotaGiB`、`expire`、`resetDay`、`billing`，以及 `notify`、`plan` 下的字段 | 下一次统计时自动读入（默认 5 分钟内），不用跑命令 |
| 新增或删除成员、改 `protocols`、改 `uuid` | 在菜单里选 **2. 应用配置文件**，或运行 `pasly CarpoolApply` |

例子里给 bob 收窄协议属于第二类，要应用一次；alice 的配额和到期日属于第一类，存盘即可。

应用时脚本先列出改动再执行。删除成员和更换 UUID 会让对应的人立刻断线，需要逐项输入 `y` 确认，所以这两类改动只能在终端里交互执行，从 cron 或管道里跑会被拒绝。

文件格式不对（JSON 写坏了、字段值不合法）时，脚本打印原因，绝不只应用一半；统计任务照常计量，沿用上次生效的配额和到期日。

不在 `members.json` 里的账号不归拼车管，脚本不会动它们，只在查看用量和应用改动时列出来。

### 停用与恢复

每次统计之后脚本判定一次：

- 配额大于 0，且本周期用量（按计费口径算）达到配额 → 停用，原因「流量已用尽」；
- 今天已过到期日 → 停用，原因「已到期」。两条都满足时记为到期。

停用就是把这个人从所有协议的 inbound 里拿掉，Xray 重载一次。超额最多晚一个统计间隔才被发现，这期间多用的流量不会在下个周期扣回。

如果这台机器装了订阅，被停用的人的订阅会换成一个连不上的占位节点，节点名写着停用原因，他在客户端里更新订阅就能看到。

恢复时用原来的 UUID 放回去，客户端不用重新导入订阅。以下几种情况会恢复：

- 到了 `resetDay`，新周期开始：全员用量清零，因超额停用、且没有到期的人恢复；
- 车主在菜单里选 **3. 清零已用流量**（全员或单人），因超额停用的人随之恢复。清零只动成员的用量，整机的数照常累计，因为服务商那边不会跟着清零；
- 车主调高了这个人的 `quotaGiB`（或改成 0），或把 `expire` 往后改，下一次统计就恢复。

改 `resetDay` 立即生效，可能让本周期提前结束，也可能拉长。

想临时停掉某个人、又保留他的 UUID，把他的 `expire` 改成已经过去的日期；要彻底移除，就从文件里删掉再应用。

**1. 查看用量** 列出每个人的已用流量、配额、到期日和状态，上方一行是整机用量（见下一节），后面附上计的是哪块网卡。

### 计费口径与整机流量

服务商按网卡的进、出计费，有的只计出站，有的进出都算，有的两者取大。拼车机是中转：成员的每个字节从一头进来、从另一头出去各一次，所以进 ≈ 出 ≈ 成员上下行合计。按这个关系，脚本给成员用量乘一个系数：`out` 和 `max` 乘 1，`both` 乘 2。配额判定、预警、页面和通知里的「已用」都是乘过的数，例子里 alice 上下行合计用了 50 GiB，就算作 100 GiB，当月停用。

口径拿不准时用默认的 `both`。多算的后果只是某个成员提前停用；少算的话整机可能先超套餐，被服务商限速时所有人一起受影响。服务商没写清楚的，可以自己量一次：客户端经代理下载一个已知大小的文件，比如 1 GB，看服务商面板涨了多少。涨约 2 GB 是双向，填 `both`；涨约 1 GB 是只计出站或取大，对拼车来说两者一样，填 `out` 或 `max` 都行。

成员的统计只是下限。Xray 统计的是代理里的数据，不含加密与协议开销、TCP/IP 包头，也不含系统更新、nginx、SSH 和扫描器打进来的流量；连接短而多时差得更多。没有一个系数能把它补准，所以成员用量不再额外乘开销，脚本另外读网卡计数，记一份整机用量：

- 计的是默认路由所在的网卡，IPv4 和 IPv6 各找一块，不是同一块就两块都算；要指定，写 `plan.interface`。读不到网卡时统计日志里记一行，这次不更新整机用量。
- 整机用量按同一个口径算：`out` 取发送，`both` 取收发之和，`max` 取两者中大的那个，和成员一起在 `resetDay` 清零。
- 车主页、**1. 查看用量** 和每日摘要里有一行「整机本周期 870 GB / 套餐 1000 GB（87%）· 成员合计 790 GB · 计费口径：双向（进 + 出）」。这一行按十进制 GB 显示，和套餐的单位一致；成员合计只算 `members.json` 里的人。两个数差得越多，说明开销和成员以外的流量越多。
- 整机用量到 `plan.warnPercent` 时发一条「整机用量预警」，每个周期一次。它只提醒车主，不会停掉任何人。
- 每次统计都读一次网卡。服务器重启后网卡计数从 0 开始，脚本认得出来并接着累计，最多丢重启前最后一个统计间隔的量。
- 拼车关着时不读网卡。关掉再开，中间没有重启、也没过清零日的，关闭期间的量在开启后第一次统计时补上；中间重启过，漏掉重启之前的那部分；过了清零日，漏掉新周期开始到重新开启的那部分。

### 只读页面

车主和成员不用登录服务器，在浏览器里就能看用量。在 **5. 页面与通知** 里选 **1. 开启页面**，再用 **2. 显示链接** 查看地址：

- 车主页：整机用量那一行，全部成员的用量、配额、到期和状态，不归拼车管的账号，配置文件里还没应用的改动，以及最近的事件；
- 成员页：每人一个，只有本人的用量、配额、计费口径、到期日、状态和下次清零日。成员页地址里的那段十六进制与他的订阅链接相同，可以和订阅一起发给本人。

页面复用订阅的 nginx，没装订阅就开不了；订阅走 HTTP 的，页面也走 HTTP。页面上没有 UUID、订阅链接、端口、域名或协议列表，也没有任何可以提交的表单，猜不中地址只会得到 404。车主链接泄露了，用 **3. 重生成车主令牌** 换一个，旧链接随即失效。

页面在每次统计时刷新，所以看到的数据最多落后一个统计间隔。

重新安装订阅会重写 nginx 的订阅配置，页面那一段 location 会被冲掉，要到下一次统计才加回来。这期间页面链接返回 404，最长一个统计间隔。

### Telegram 通知

先在 Telegram 里建一个 bot，拿到 bot token 和接收消息的 chat id（群组和频道的 chat id 是负数）。在 **5. 页面与通知** 里选 **4. 配置 Telegram 通知** 填入，token 输入时不回显；再用 **5. 发送测试消息** 确认能收到。配置存在 `/etc/Proxy-agent/carpool/telegram.conf`，权限 600；**6. 关闭 Telegram 通知** 会删掉这个文件。

会通知的事件：成员停用、成员恢复、用量预警、整机用量预警、即将到期、新周期清零（附上期各人与整机的用量）、配置已应用、配置文件无效、统计连续失败 3 次及之后的恢复、账户修改失败、内核不再是 Xray、统计任务异常退出，外加每日摘要。同一件事不会反复发：预警每人每周期一次，整机预警每周期一次，配置文件无效按文件内容只提醒一次。

消息里只有 `notify.label`、成员名、流量数字和日期，不含 UUID、链接、主机名或 IP。发送失败只记日志，不影响停用和恢复。

发送时 bot token 会出现在 `curl` 的命令行参数里，同一台机器上的其他用户用 `ps` 看得到。只有 root 一个用户的 VPS 不受影响。

### 改统计间隔

统计任务默认每 5 分钟跑一次。要改，就用 `crontab -e` 编辑含 `install.sh CarpoolTick` 的那一行，比如改成每分钟一次：

```
* * * * * PROXY_AGENT_DIR=/etc/Proxy-agent /bin/bash /etc/Proxy-agent/install.sh CarpoolTick >> /etc/Proxy-agent/crontab_carpool.log 2>&1
```

只改开头的五个时间字段，后面原样保留。脚本发现已有这一行就不会再加，改过的间隔不会被覆盖。统计日志在 `/etc/Proxy-agent/crontab_carpool.log`。

### 拼车开着时的限制

- **4. 添加用户** 和 **5. 删除用户** 不再可用，账号改由 `members.json` 管理；
- 不能切换到 sing-box 内核，也不能安装 Hysteria2 或 TUIC，要先关闭拼车；
- Xray 不走 splice 转发：CPU 占用略高（几十 Mbit/s 下测不出差别，千兆满速没测过）；连着却长时间没有流量的连接 4–5 分钟后断开，原来是 24 小时。

### 关闭拼车

再选一次 **4**，这时它显示为「关闭拼车」。关闭的意思是不再计量，不等于把所有人放回来。脚本先统计一次，再列出各组成员请你确认：

| 成员状态 | 关闭时的处理 |
|----------|--------------|
| 正常 | 不动 |
| 因超额停用 | 恢复：计量停了，超额无从谈起。但已过到期日的改记为到期，不恢复 |
| 因到期停用 | 保持停用：关闭后没人再检查到期日，放回来就等于永久有效 |

确认后脚本还会再问一次，要不要把已到期的也一并恢复，默认不恢复。

关闭之后，统计接口和 cron 任务撤掉，Xray 恢复 splice 转发，页面删除，添加 / 删除用户恢复可用，到期日不再执行。`members.json`、`telegram.conf` 和已统计的用量都保留，同一周期内再开启会接着算。

## 链式代理详解

链式代理是本脚本的高级功能，可以实现多跳代理（流量经过多台服务器转发），常见用途：
- 通过多跳来隐藏真实IP
- 利用不同地区的服务器优势（线路机+落地机）
- 实现分流（不同网站走不同出口）

### 基本概念

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  您的    │ → │  入口    │ → │  中继    │ → │  出口    │ → 互联网
│  设备    │    │  节点    │    │ (可选)   │    │  节点    │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
```

- **入口节点**：您的设备直接连接的服务器
- **中继节点**（可选）：中间转发节点，可以有多个
- **出口节点**：最终连接互联网的服务器

### 进入链式代理菜单

1. 运行 `pasly`
2. 选择 **3. 链式代理管理**

您会看到：
```
链式代理管理
================================================
1. 快速配置向导 [推荐]
2. 查看链式状态
3. 测试链式连接
4. 高级设置
5. 卸载链式代理
6. 外部节点管理
7. 按协议分流设置
```

### 快速配置向导支持的角色

进入 **3. 链式代理管理** → **1. 快速配置向导** 后，可以选择以下角色：

| 选项 | 角色 | 说明 |
|------|------|------|
| 1 | 出口节点（Exit） | 链路终点，直连互联网，生成配置码供上游导入 |
| 2 | 中继节点（Relay） | 链路中间节点，导入下游配置码再生成新的配置码供上游使用，支持多层中继 |
| 3 | 入口节点 - 单链路 | 用户设备连接的服务器，导入出口或中继的配置码 |
| 4 | 入口节点 - 多链路分流 | 配置多条出口链路，按规则分流到不同出口 |
| 5 | 手动配置入口节点 | 不通过配置码、手动输入出口信息（仅支持单跳） |

下面以最常见的三种场景演示。

### 场景一：配置出口节点（落地机）

**适用情况**：您有一台落地机，想让它作为出口节点。

1. 在落地机上运行 `pasly`
2. 进入 **3. 链式代理管理** → **1. 快速配置向导**
3. 选择 **1. 出口节点**

配置过程：
```
请输入端口 [回车随机生成]:
```
直接回车即可使用随机端口。

```
是否限制仅允许指定入口节点连接? [y/n]
```
- 输入 `y`：更安全，只有指定的入口节点可以连接
- 输入 `n`：任何知道配置的节点都可以连接

配置完成后，脚本会显示一段 **配置码**，以 `chain://` 开头，类似：
```
=================================================
出口节点配置码（请复制并保存）:
chain://ss2022@1.2.3.4:12345?key=BASE64_ENCODED_KEY&method=2022-blake3-aes-128-gcm
=================================================
```

> **重要**：请完整复制这段配置码（含 `chain://` 前缀），稍后在入口节点配置时需要使用。
> 多跳入口节点使用 V2 格式 `chain://v2@BASE64_JSON`，也由脚本自动生成。

### 场景二：配置入口节点（单链路模式）

**适用情况**：您有一台入口机，想连接到一个出口节点。

1. 在入口机上运行 `pasly`
2. 进入 **3. 链式代理管理** → **1. 快速配置向导**
3. 选择 **3. 配置为入口节点 - 单链路模式**

配置过程：
```
请粘贴出口节点配置码:
```
粘贴之前在出口节点获取的配置码，回车确认。

脚本会自动解析并显示配置信息：
```
服务器地址: 1.2.3.4
端口: 12345
加密方式: 2022-blake3-aes-128-gcm
```

确认无误后，脚本会自动配置并重启服务。

### 场景三：多链路分流模式

**适用情况**：您想让不同的网站走不同的出口节点。

例如：
- 观看 Netflix → 走美国出口
- 使用 ChatGPT → 走日本出口
- 其他网站 → 走默认出口

#### 配置步骤

1. 在入口机上运行 `pasly`
2. 进入 **3. 链式代理管理** → **1. 快速配置向导**
3. 选择 **4. 配置为入口节点 - 多链路分流模式**

#### 添加第一条链路

```
添加链路 #1
请选择添加方式:
1. 使用配置代码添加（自建出口节点）
2. 使用外部节点添加（第三方节点）
```

**使用配置码**：粘贴出口节点生成的配置代码

**使用外部节点**：选择已添加的外部节点（见[外部节点管理](#外部节点管理)）

```
请输入链路名称 [默认: chain_1]:
```
建议使用有意义的名称，如 `us_netflix`、`jp_ai` 等。

#### 配置分流规则
> 预设分流规则模版使用MetaCubeX 维护的规则集
```
请选择要分流到此链路的流量类型:
1. 流媒体 (Netflix/Disney+/YouTube/...)
2. AI服务 (OpenAI/Bing/...)
3. 社交媒体 (Telegram/Twitter/...)
4. 开发者 (GitHub/GitLab/...)
5. 游戏 (Steam/Epic/...)
6. Google服务
7. 自定义域名规则
8. 跳过，不配置分流
```

选择对应数字，即可将该类流量分流到此链路。

#### 继续添加更多链路

```
是否继续添加链路? [y/n]
```
输入 `y` 继续添加，输入 `n` 完成配置。

#### 设置默认链路

```
请选择默认链路（未匹配规则的流量将走默认链路）:
1. chain_us
2. chain_jp
3. direct (直连，不经过任何出口)
```

### 查看链式状态

配置完成后，可以随时查看当前链式代理状态：

1. 进入 **3. 链式代理管理** → **2. 查看链式状态**

显示内容包括：
- 已配置的链路数量
- 每条链路的出口信息
- 分流规则配置
- 默认链路

### 测试链式连接

验证链式代理是否正常工作：

1. 进入 **3. 链式代理管理** → **3. 测试链式连接**

测试结果示例：
```
✅ chain_us (1.2.3.4:12345) - 延迟: 150ms
✅ chain_jp (5.6.7.8:23456) - 延迟: 80ms
❌ chain_hk (9.10.11.12:34567) - 连接失败
```

如果显示连接失败，请检查：
- 出口节点是否在线
- 防火墙是否开放对应端口
- 配置代码是否正确

## 外部节点管理

外部节点功能允许您使用第三方提供的节点（如购买的机场节点、朋友分享的节点）作为链式代理的出口。

- Shadowsocks（同时兼容 Shadowsocks 2022）
- SOCKS5
- Trojan

### 添加外部节点

```

节点名称: 美国节点
```

确认添加后，该节点就可以在多链路分流中使用了。

1. 选择 **4. 测试节点连接**

测试结果：

### 将外部节点设为出口

2. 选择要使用的节点

## 故障排查指南

### 第一步：跑一次系统诊断

遇到任何问题，先跑一遍系统诊断（只读检测，不会动配置）：

```bash
pasly doctor
# 或在菜单里选 23
```

会按 **系统 / 安装 / 内核 / 配置 / 网络 / 证书 / 防火墙** 七段输出 PASS / WARN / FAIL / SKIP，最后给一个汇总行。哪一段红字 FAIL 就先看那段——能省下大量盲找时间。

### 服务无法启动

**现象**：执行启动命令后，服务状态显示未运行。

**排查步骤**：

1. **查看日志**
   - 进入 **16. 核心管理** → 选择对应内核 → **查看日志**
   - 查找包含 `error`、`failed`、`invalid` 的行

2. **常见原因及解决方法**

   | 日志关键词 | 可能原因 | 解决方法 |
   |-----------|---------|---------|
   | `port already in use` | 端口被占用 | 更换端口或停止占用该端口的程序 |
   | `certificate` | 证书问题 | 重新申请证书（菜单 9） |
   | `permission denied` | 权限不足 | 确保以 root 用户运行 |
   | `config error` | 配置文件错误 | 检查配置或重新安装 |

3. **手动启动查看详细错误**
   ```bash
   # Xray（脚本使用 -confdir 自动合并 conf/ 下所有 *.json）
   /etc/Proxy-agent/xray/xray run -confdir /etc/Proxy-agent/xray/conf

   # sing-box（运行前确保 sing-box merge 已生成 conf/config.json）
   /etc/Proxy-agent/sing-box/sing-box run -c /etc/Proxy-agent/sing-box/conf/config.json
   ```

### 无法连接代理

**现象**：客户端配置正确，但无法连接。

**排查步骤**：

1. **检查服务状态**
   ```bash
   # Xray
   systemctl status xray

   # sing-box
   systemctl status sing-box
   ```

2. **检查端口是否开放**
   ```bash
   # 检查端口是否监听
   ss -tlnp | grep 端口号

   # 检查防火墙
   ufw status        # Ubuntu
   firewall-cmd --list-all  # CentOS
   ```

3. **检查域名解析**
   ```bash
   ping 您的域名
   ```
   确保解析的 IP 是您的 VPS IP。

4. **检查证书有效期**
   - 进入 **9. 证书管理**
   - 查看证书剩余天数

### 证书申请失败

**现象**：安装过程中证书申请步骤失败。

**常见原因**：

1. **域名未正确解析**
   - 确保域名 A 记录指向 VPS IP
   - 等待 DNS 生效（可能需要几分钟）

2. **80/443 端口被占用**
   ```bash
   # 检查端口占用
   ss -tlnp | grep -E ':80|:443'

   # 如果被 nginx 占用，先停止
   systemctl stop nginx
   ```

3. **申请次数超限**
   - Let's Encrypt 每周每域名限制 5 次
   - 等待一周后重试，或使用 DNS API 方式

4. **使用 DNS API 方式申请**（推荐）
   - DNS API 在首次安装或重新安装时由证书申请向导提示选择，按提示输入 Cloudflare 或阿里云的 API 凭据即可
   - 适合 80/443 被占用、NAT VPS 或需要泛域名证书的场景
   - 支持 Cloudflare、阿里云等

### 链式代理不工作

**现象**：配置了链式代理，但流量未经过出口节点。

**排查步骤**：

1. **检查出口节点状态**
   - 在出口节点服务器上检查服务是否运行
   - 检查防火墙是否开放配置的端口

2. **测试链式连接**
   - 进入 **3. 链式代理管理** → **3. 测试链式连接**

3. **检查配置代码**
   - 确保配置代码完整复制，没有多余空格
   - 重新配置一次

4. **查看入口节点日志**
   - 查找是否有连接出口节点失败的错误

### 速度很慢

**排查方向**：

1. **检查线路质量**
   ```bash
   # 测试到出口节点的延迟
   ping 出口节点IP

   # 测试丢包率
   mtr 出口节点IP
   ```

2. **检查服务器负载**
   ```bash
   top
   ```
   如果 CPU 使用率很高，可能需要升级配置。

3. **启用 BBR**
   - 进入 **18. 安装BBR/DD脚本**
   - 安装 BBR 可以提升 TCP 传输效率

4. **检查协议选择**
   - UDP 协议（Hysteria2、TUIC）通常更快
   - 可以尝试不同协议

## 升级与迁移提示

下面是从旧版本升级时**可能注意到**的行为变化。这里只列出真正会让用户看到不同/需要动手的项；其它修复对最终用户透明，不必关心。

### Xray-core：「升级」会装回 v26.3.27

**适用对象**：用 Xray 内核、且装有 Reality（菜单里的 VLESS+Reality+Vision 或 XHTTP）的用户。

**现象**：更新脚本后进 16 → 1「升级 Xray-core」，提示「将把 Xray-core 从 v26.10.x 换成 v26.3.27」。

**原因**：Xray-core 26.9.8 起 Reality 服务端要求客户端带 X25519MLKEM768 密钥份额，官方 sing-box 客户端不带，握手失败报 `reality verification failed`。脚本发出的 sing-box 订阅因此在新版内核上连不上，所以默认钉回最后一个两边都能连的稳定版。

**要不要处理**：
- 有人用 sing-box 系客户端（sing-box、SFI/SFA、Karing 这类）连你的 Reality 节点：按提示换成 v26.3.27。
- 只有 mihomo / Xray 系客户端：可以留在新版，或用 16 → 10 显式装最新版。
- sing-box 上游修复发布后脚本会解钉，届时「升级」重新指向最新版。

### Cloudflare WARP：升级后 `apt update` 可能有 legacy keyring 警告

**适用对象**：之前用过菜单 11 安装过 WARP，并且系统是 Debian / Ubuntu 的用户。

**现象**：升级到新脚本之后再跑 `apt update` 看到一行
```
W: ... Key is stored in legacy trusted.gpg keyring (/etc/apt/trusted.gpg)
```

**原因**：旧版脚本用的是已经被 Debian 12 / Ubuntu 24.04 移除的 `apt-key add` 命令，把 Cloudflare 公钥写进了老的 `/etc/apt/trusted.gpg`。新版脚本改用现代的 `signed-by=/usr/share/keyrings/cloudflare-warp-archive-keyring.gpg`，并在每次安装时重新拉取最新公钥（应对 Cloudflare 的 key rotation——例如 2025-12-04 的那次）。

**要不要处理**：
- **不影响功能**——警告只是提示老 key 还在传统钥匙串里没清掉，新仓库的签名校验已经走新 key。
- 想消除警告的话，手动执行：
  ```bash
  # 列出所有老 key
  apt-key list 2>/dev/null | grep -B1 -A1 -i "cloudflare\|warp"
  # 找到 fingerprint 后删除（命令在 Debian 12 / Ubuntu 24.04 上不存在，直接删除文件即可）
  apt-key del <fingerprint>
  # 或者如果系统已经移除 apt-key：
  sudo rm -f /etc/apt/trusted.gpg
  ```

### Hysteria2：obfs 密码含特殊字符的用户请重新生成订阅

**适用对象**：装了 Hysteria2 协议、且 obfs 密码里**包含 `"`、`\`、`%`、空格或其它非字母数字字符**的用户。

**现象**：旧版本生成的订阅链接、二维码可能漏掉 obfs 字段，或 obfs 密码被截断/转义错误，导致客户端连不上、或连上了没启用混淆。

**原因**：旧版本对 obfs 密码的 JSON 转义和 URL 编码不到位（commit `99a2854` / `147c922` 修复）。

**怎么处理**：升级后做一次：
1. `pasly` → `7. 用户管理` → `2. 查看订阅`
2. 把新生成的订阅链接重新导入客户端（V2rayN / Clash 等）
3. obfs 密码本身不需要改，重新生成订阅即可。

如果你的 obfs 密码只有字母数字，旧订阅本来就是对的，**不用动**。

### CDN 节点管理（菜单 10）已下线

**适用对象**：之前用过菜单 10 设置过 CDN 优选 IP / 域名的用户。

**为什么删**：

- Cloudflare 政策进一步收紧，**明确禁止**把它的 CDN 当代理使用，社区道德层面对这种用法也不认可
- CDN 优选对中国大陆用户的实际收益**因网络环境差异很大**，并非通用提速
- 想优选回源 IP 的用户更应该走 Cloudflare Workers / 自建中转 / 商业 CDN，而不是绕 Cloudflare 免费版的 ToS

**自动迁移**：**不动你的现有设置**。订阅生成路径（`subscribe()`）仍然读 `/etc/Proxy-agent/cdn` 文件，已设过 CDN 的用户**订阅链接不变**——只是失去 UI 入口。

**清除/修改 CDN 设置**：

```bash
# 完全清除 CDN，订阅恢复用 VPS 直连域名
rm /etc/Proxy-agent/cdn

# 或者改为新的 CDN 域名 / IP
echo "your.new.domain.or.ip" > /etc/Proxy-agent/cdn

pasly  # → 7 → 2  重新查看订阅，确认链接更新
```

### BT 下载管理（菜单 13）已下线

**适用对象**：之前用过菜单 13 启用过「禁止下载 BT」的 Xray 用户。

**为什么删**：

- VPS 主机商是否禁 BT 这件事，用户在购买时本就该自己了解；如果确实不允许，自己用的时候注意点就行了
- 仅 Xray 支持，sing-box 用户用不上
- 维护一个仅 Xray、仅 niche 场景的菜单不划算

**自动迁移**：**Xray 09_routing.json 里的 BT 屏蔽规则继续生效**——已经启用过的用户，BT 仍然被丢入 blackhole_out（保留你原来的意图）。

**关闭 BT 屏蔽（如果想恢复）**：

```bash
jq '.routing.rules |= map(select((.outboundTag != "blackhole_out") or (.protocol // [] | index("bittorrent") | not)))' \
   /etc/Proxy-agent/xray/conf/09_routing.json > /tmp/x \
&& mv /tmp/x /etc/Proxy-agent/xray/conf/09_routing.json

pasly  # → 16 → 重启 Xray
```

> 这条 jq 只删除「outboundTag=blackhole_out **且** protocol 包含 bittorrent」的规则，不影响其它 blackhole 规则（如 SNI 反向代理用的）。

### 域名黑名单功能（菜单 15）已下线

**适用对象**：之前用过菜单 15 添加过域名屏蔽规则的用户。

**为什么删**：服务端做域名屏蔽对个人代理用例价值很低——客户端 Clash / sing-box 客户端 / NekoBox 的 rule 系统本来就更灵活、控制粒度更细。同时实现里用的 `block` outbound 在 sing-box 1.13 已彻底删除，留着会让 `sing-box check` FATAL，整个 sing-box 起不来。综合下来直接下线最干净。

**自动迁移**：sing-box 侧——脚本下次启动并 merge 配置时，会自动移除以下 5 个废弃片段（不需要你手动做）：

```
/etc/Proxy-agent/sing-box/conf/config/{block_domain_outbound,block_domain_route,
                                       cn_block_outbound,cn_block_route,
                                       cn_01_google_play_route}.json
```

**Xray 侧不会被自动清理**：你的 `09_routing.json` 里指向 `blackhole_out` 的规则**仍然正常工作**，流量行为不变；只是失去 UI 管理能力。如果你已经不想要这些规则，手动跑：

```bash
jq '.routing.rules |= map(select(.outboundTag != "blackhole_out" or has("protocol")))' \
   /etc/Proxy-agent/xray/conf/09_routing.json > /tmp/x \
&& mv /tmp/x /etc/Proxy-agent/xray/conf/09_routing.json
pasly  # → 16 → 重启
```

> `has("protocol")` 那段是为了**保留** BT 屏蔽规则（它也用 blackhole_out 但带 protocol 字段，是另一个菜单的合法功能）。

**迁移到客户端做**：如果你确实需要域名屏蔽，在客户端层做更合适：
- Clash / mihomo：在 `rules` 段加 `DOMAIN-SUFFIX,baidu.com,REJECT`
- sing-box 客户端：route rule + `action: reject`
- NekoBox / Hiddify：路由规则界面直接配

### sing-box ≥ 1.11 / 1.13 / 1.14 配置 schema 演进

**适用对象**：自己手动改过 sing-box 配置文件、或者使用很旧版本（脚本之前的）安装了 sing-box 的用户。

**现象**：升级 sing-box 内核到 1.13+ 后，老配置可能因 `domain_strategy` / `default_domain_resolver` / `sniff` schema 变更而 FATAL 拒绝启动。出站上的 `domain_strategy` 在 1.12 弃用、**1.14 移除**。

**怎么处理**：
- 脚本本身已自动剥离/迁移这些字段，跑一次 `pasly doctor` 看 Config 段是否 PASS 即可
- 出站的 `domain_strategy` 会在每次启动合并配置时自动改写成等价的 `domain_resolver`，看到「已把旧版 outbound domain_strategy 迁移为 domain_resolver」是正常的，只打印一次
- rule_set 的 `download_detour` 同样在每次启动合并时自动改成 1.14 的 `http_client` + 顶层 `http_clients`（1.14 弃用、1.15 起拒绝启动）；内核还在 1.14 以下时反向剥离，升级内核后自动恢复。看到「已把 rule_set 的 download_detour 迁移为 http_client」或「已剥离 rule_set 的 http_client 字段」都是正常的
- Reality 入站现在显式写 `minClientVer: 1.8.0`（老配置在 Xray 启动前自动补上，看到「已为 Reality 入站补上 minClientVer」是正常的）：Xray-core 26.7 起不写就默认 26.3.27，会拒绝 sing-box / mihomo 这类客户端，而脚本自己发的订阅就包含它们。只用新版 Xray 客户端、想跟随 Xray 收紧策略的，可以手动改成 `26.3.27`
- 如果 FAIL：菜单 1 重新安装受影响的协议、或菜单 22 → 4 找一个旧版本备份回滚

```bash
pasly doctor          # 只读系统诊断（菜单 23 同义）
pasly --dry-run       # 预演模式：装/卸/链式代理操作只打印计划，不真改系统
```

## 常见问题解答

### Q: 可以同时安装多个协议吗？

**A**: 可以。使用 **2. 任意组合安装** 可以选择安装多个协议。安装后，所有协议共享同一用户列表。

### Q: 如何更换端口？

**A**: 重新安装（菜单 1 或 2）时在端口提示处填新端口即可。只用 Xray 内核的话，也可以用 **12. 添加新端口** 额外开几个端口，原端口不变；sing-box 内核不支持这个菜单。

### Q: 端口默认是怎么选的？

**A**: 看起来像 HTTPS 的协议，端口提示处直接回车取 443：VLESS Vision、Trojan、Reality、Reality XHTTP、Naive、HTTPUpgrade、AnyTLS。443 已被占，就依次取 8443、2053、2083、2087、2096 里第一个空着的，这几个也是 Cloudflare 会转发的 HTTPS 端口；六个全被占才回落随机端口。Hysteria2 与 TUIC 走 UDP，同样从 443/udp 起取，和 TCP 的 443 互不冲突，两个一起装时 Hysteria2 先拿。VLESS WS、VMess WS 与 Shadowsocks 2022 仍默认随机端口。

「已被占」指本机别的程序在用，或这次安装之后仍会留着的其他协议在用。手填已被占的端口，脚本会请你换一个；重装时上次的端口若已被这次安装的其他协议拿走，也会提示重选。带域名的 Xray 里 VLESS Vision 优先拿 443：先用一键 Reality 把 Reality 装在 443、之后再装带域名的 Xray，Reality 会改到备选端口，客户端要重新导入它的链接或更新订阅。

Xray 内核装了 VLESS Vision 时，脚本还会在 80 上把访问这个域名的请求 301 跳到 https，和普通网站一样；宝塔 / 1Panel 场景、或 80 被别的程序占着时不加。sing-box 内核不加，因为它的 443 背后没有伪装站。

### Q: Hysteria2 的拥塞控制和混淆怎么选？

**A**: 拥塞控制默认 BBR，多数线路用它就好。Brutal 按你填的带宽固定速率发包，丢包重的线路上更快，但带宽填得比实际大会挤占整条线路，所以改成了可选项。选 Brutal 时订阅会把带宽一并发给客户端；选 BBR 时订阅不带带宽，客户端也走 BBR。

混淆默认不开。salamander 让 QUIC 流量不像 QUIC。sing-box 1.14 起还能选 gecko，它把 QUIC 握手包切片，Hysteria 官方目前标为实验性；客户端要 sing-box 1.14、Hysteria 2.9.2 或 mihomo 1.19.26 及以上，旧客户端导入时可能悄悄丢掉混淆而连不上。混淆密码直接回车会随机生成，手填只能用字母、数字和 `. _ ~ -`。

没通过认证的 HTTP/3 请求看到的是伪装站的网页，内容取自伪装站的静态文件；sing-box 内核原本没装伪装站的，装 Hysteria2 时会顺手装一个。宝塔 / 1Panel 场景不开这一项，这类请求得到 404。

已经装好的 Hysteria2 不会自动改。想换成新的默认值，在 Hysteria2 管理里选「重新安装」，之后客户端更新一次订阅。

### Q: VMess 和 Trojan 还能用吗？

**A**: 能装、能连，订阅照常生成。Xray 从 26.1.23 起把 VMess 和 Trojan 标为弃用，读配置时会打警告；sing-box 目前仍支持它们，但不少客户端用的是 Xray 内核，所以新部署别再选，安装菜单里也标出来了。已经在用的可以这样迁：

- **VMess WS 换成 VLESS WS**：两者都能挂在 CDN 后面。重新做一次「任意组合安装」，选 1、不选 3。
- **VMess HTTPUpgrade 换成 VLESS WS**：同上，选 1、不选 11。
- **Trojan 换成 VLESS Vision**：选 0、不选 4。Xray 内核的组合安装本来就带 0。

重装时按提示沿用上次的配置，账号保持不变。装完客户端更新一次订阅，新节点出现、旧节点消失。

### Q: 域名必须要用吗？

**A**: 不一定。以下协议不需要域名：
- VLESS + Reality + Vision（菜单 19 一键安装，或任意组合安装里只选 7）
- Shadowsocks 2022（sing-box 内核）

其余协议都需要域名和证书，包括 Hysteria2 与 TUIC（脚本只用 ACME 签发的证书，不生成自签证书）。VLESS + Reality + XHTTP 本身不用证书，但会与 VLESS TCP/Vision 一起装，所以也需要域名。

另外，Reality 不能挂在 CDN 后面；要走 CDN 只能选 WS 或 HTTPUpgrade，端口也要选 CDN 会转发的（Cloudflare 的 HTTPS 只转发 443、2053、2083、2087、2096、8443）。

### Q: 支持使用宝塔面板吗？

**A**: 支持。脚本会自动检测宝塔面板并调整配置，避免端口冲突。但建议在干净系统上安装以获得最佳体验。

### Q: 如何备份配置？

**A**: 重要配置文件位于 `/etc/Proxy-agent/` 目录。可以定期备份此目录：
```bash
tar -czvf proxy-backup.tar.gz /etc/Proxy-agent/
```

### Q: 忘记了账号信息怎么办？

**A**: 运行 `pasly`，选择 **7. 用户管理** → **1. 查看账号**，即可再次查看所有账号信息。

### Q: 如何彻底卸载？

**A**:
1. 运行 `pasly`
2. 选择 **20. 卸载脚本**
3. 确认卸载

卸载后，所有配置和数据将被删除。

### Q: 更新脚本会影响现有配置吗？

**A**: 不会。更新脚本只更新脚本本身，不会修改已有的代理服务配置。如果担心兼容性问题，可以先使用 **22. 脚本版本管理** 备份当前版本。

### Q: 链式代理和普通代理有什么区别？

**A**:
- **普通代理**：您的设备 → 代理服务器 → 互联网
- **链式代理**：您的设备 → 入口节点 → （中继节点）→ 出口节点 → 互联网

链式代理可以更好的隐藏真实IP，或利用不同服务器的线路或IP优势。

### Q: 外部节点是什么意思？

**A**: 外部节点是指您没有 root 权限的第三方节点，比如：
- 购买的机场节点
- 朋友分享的节点
- 与他人合租的 VPS 上的节点

您只有节点的连接信息（服务器、端口、密码等），可以将其作为链式代理的出口使用。
